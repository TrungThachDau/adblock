# Adblock Engine IPC Protocol Specification

## 1. Overview & Transport

The Adblock Engine IPC protocol defines the newline-delimited JSON (NDJSON) communication contract between the core packet filtering engine and client applications (such as the WinUI 3 management GUI or CLI tools).

### 1.1 Transport Layer
- **Endpoint**: `\\.\pipe\<AppName>.engine`
  - Default: `\\.\pipe\adblock.engine`
  - Configurable via `--pipe-name <name>` on engine startup.
- **Direction**: Bidirectional (`PIPE_ACCESS_DUPLEX`).
- **Mode**: Byte stream (`PIPE_TYPE_BYTE | PIPE_READMODE_BYTE`).
- **Framing**: Newline-delimited JSON (NDJSON) encoded in **UTF-8** (without BOM). Every message is a single valid JSON object terminated by `\n` or `\r\n`.
- **Concurrency**: The engine supports multiple concurrent client connections. State modifications and events are synchronized across all connected clients.

---

## 2. Message Framing & Formats

### 2.1 Request Format (Client -> Engine)
Clients send a JSON object specifying an identifier, command name, and optional parameters:

```json
{
  "id": 1,
  "cmd": "<command_name>",
  "params": {}
}
```

- `id` (integer or string, required): Unique identifier generated by the client. The engine echoes this exact identifier in its response.
- `cmd` (string, required): The command name (e.g. `get_status`, `start`, `stop`). Note: `method` is accepted interchangeably with `cmd` for JSON-RPC 2.0 compatibility.
- `params` (object, optional): Key-value parameters specific to the command. Defaults to `{}` if omitted.

### 2.2 Success Response Format (Engine -> Client)
On successful execution, the engine replies:

```json
{
  "id": 1,
  "result": {}
}
```

- `id` (integer or string): Matches the corresponding request `id`.
- `result` (object): Command-specific output payload.

### 2.3 Error Response Format (Engine -> Client)
When a command fails or is invalid:

```json
{
  "id": 1,
  "error": {
    "code": -32601,
    "message": "Command not found",
    "data": null
  }
}
```

#### Standard Error Codes
| Code | Constant | Description |
|---|---|---|
| `-32700` | `ParseError` | Invalid JSON received by the pipe server. |
| `-32600` | `InvalidRequest` | Message is missing required `id` or `cmd` fields. |
| `-32601` | `MethodNotFound` | Unknown command name. |
| `-32602` | `InvalidParams` | Invalid or missing arguments in `params`. |
| `-32603` | `InternalError` | Engine encountered an unhandled internal exception. |
| `-32000` | `ServerError` | Operation failed (e.g., driver unavailable, file I/O error). |

### 2.4 Asynchronous Push Events (Engine -> Client)
Spontaneous events emitted by the engine to all connected clients:

```json
{
  "event": "<event_name>",
  "data": {}
}
```

- `blocked_query`: Emitted when an outbound DNS or TLS query matches a blocklist rule and is blocked.
- `stats_update`: Broadcast periodically (e.g. every 1000ms) with aggregate metrics.

## 3. Command Reference

### 3.1 `start`
Starts packet interception and blocking via the WinDivert kernel driver.

#### Request
```json
{"id": 1, "cmd": "start", "params": {}}
```

#### Response
```json
{
  "id": 1,
  "result": {
    "status": "ok",
    "state": "running"
  }
}
```

---

### 3.2 `stop`
Stops packet interception. When stopped, all outbound DNS, TLS, and UDP traffic passes through uninspected and unblocked.

#### Request
```json
{"id": 2, "cmd": "stop", "params": {}}
```

#### Response
```json
{
  "id": 2,
  "result": {
    "status": "ok",
    "state": "stopped"
  }
}
```

---

### 3.3 `get_status`
Retrieves engine metadata, version, operational state, rule counts, and list configuration.

#### Request
```json
{"id": 3, "cmd": "get_status", "params": {}}
```

#### Response
```json
{
  "id": 3,
  "result": {
    "name": "engine-rs",
    "version": "1.0.0",
    "state": "running",
    "active_rules_count": 142850,
    "allowlist_count": 35,
    "lists_count": 3,
    "uptime_seconds": 3600
  }
}
```

- `name`: Engine binary identifier (`"engine-rs"` or `"engine-cs"`).
- `version`: Engine semantic version string (e.g. `"1.0.0"`).
- `state`: `"running"` or `"stopped"`.
- `active_rules_count`: Total number of active domain block rules loaded.
- `allowlist_count`: Total number of active exception/allowlist rules loaded.
- `lists_count`: Number of external blocklist files configured.
- `uptime_seconds`: Engine process uptime in seconds.

---

### 3.4 `set_lists`
Configures the list of enabled blocklist file paths. Triggers immediate re-parsing and replaces all previously loaded blocklist rules.

#### Request
```json
{
  "id": 4,
  "cmd": "set_lists",
  "params": {
    "paths": [
      "C:\\ProgramData\\Adblock\\lists\\easylist.txt",
      "C:\\ProgramData\\Adblock\\lists\\adguard_dns.txt",
      "C:\\ProgramData\\Adblock\\lists\\hosts.txt"
    ]
  }
}
```

#### Response
```json
{
  "id": 4,
  "result": {
    "status": "ok",
    "loaded_lists": 3,
    "active_rules_count": 142850,
    "failed_paths": []
  }
}
```

---

### 3.5 `set_allowlist`
Configures custom user allowlist rules or allowlist file paths. Rules can be plain hostnames (`good.example.com`) or ABP exception syntax (`@@||good.example.com^`).

#### Request
```json
{
  "id": 5,
  "cmd": "set_allowlist",
  "params": {
    "rules": [
      "safe.example.com",
      "@@||trusted-cdn.net^"
    ],
    "paths": [
      "C:\\ProgramData\\Adblock\\custom-whitelist.txt"
    ]
  }
}
```

#### Response
```json
{
  "id": 5,
  "result": {
    "status": "ok",
    "allowlist_count": 42
  }
}
```

---

### 3.6 `reload`
Reloads and re-parses all currently configured blocklist files (`set_lists`) and allowlist sources (`set_allowlist`) from disk without modifying paths or restarting the engine.

#### Request
```json
{"id": 6, "cmd": "reload", "params": {}}
```

#### Response
```json
{
  "id": 6,
  "result": {
    "status": "ok",
    "active_rules_count": 142850,
    "allowlist_count": 42
  }
}
```

---

### 3.7 `get_stats`
Returns cumulative traffic statistics, runtime duration, and process RAM usage.

#### Request
```json
{"id": 7, "cmd": "get_stats", "params": {}}
```

#### Response
```json
{
  "id": 7,
  "result": {
    "allowed_count": 48210,
    "blocked_count": 3491,
    "dns_queries": 32050,
    "dns_blocked": 2980,
    "tls_queries": 19651,
    "tls_blocked": 511,
    "quic_dropped": 142,
    "uptime_seconds": 7240,
    "ram_bytes": 18432000,
    "ram_mb": 17.58
  }
}
```

- `allowed_count`: Total queries permitted (clean traffic + allowlisted exceptions).
- `blocked_count`: Total queries intercepted and blocked (`dns_blocked + tls_blocked + quic_dropped`).
- `dns_queries`: Total outbound DNS queries parsed.
- `dns_blocked`: Synthetic `NXDOMAIN` packets injected.
- `tls_queries`: Outbound TLS ClientHello handshakes parsed.
- `tls_blocked`: Synthetic `TCP RST` packets injected.
- `quic_dropped`: Outbound UDP 443 packets dropped unconditionally.
- `uptime_seconds`: Engine uptime in seconds.
- `ram_bytes`: Process Working Set / Private Bytes in bytes.
- `ram_mb`: Process memory usage in megabytes.

---

### 3.8 `get_recent_blocked`
Retrieves a circular buffer of recently blocked queries for diagnostic and UI activity views.

#### Request
```json
{
  "id": 8,
  "cmd": "get_recent_blocked",
  "params": {
    "limit": 50
  }
}
```

- `limit` (integer, optional, default: 50, max: 500): Maximum number of entries to return.

#### Response
```json
{
  "id": 8,
  "result": {
    "items": [
      {
        "id": "1042",
        "timestamp": 1728553893,
        "protocol": "DNS",
        "client_ip": "192.168.1.15",
        "domain": "adservice.google.com",
        "matched_rule": "||adservice.google.com^",
        "source_list": "easylist.txt"
      },
      {
        "id": "1041",
        "timestamp": 1728553890,
        "protocol": "TLS",
        "client_ip": "192.168.1.15",
        "domain": "tracker.analytics.com",
        "matched_rule": "tracker.analytics.com",
        "source_list": "hosts.txt"
      }
    ]
  }
}
```

## 4. Asynchronous Push Events

### 4.1 `blocked_query`
Emitted immediately upon dropping a packet and injecting synthetic responses:

```json
{
  "event": "blocked_query",
  "data": {
    "id": "1043",
    "timestamp": 1728553905,
    "protocol": "DNS",
    "client_ip": "192.168.1.15",
    "domain": "telemetry.adnetwork.org",
    "matched_rule": "||adnetwork.org^",
    "source_list": "easylist.txt"
  }
}
```

### 4.2 `stats_update`
Emitted periodically to allow connected UIs to refresh telemetry without polling:

```json
{
  "event": "stats_update",
  "data": {
    "allowed_count": 48215,
    "blocked_count": 3492,
    "uptime_seconds": 7245,
    "ram_bytes": 18450000,
    "ram_mb": 17.60
  }
}
```
